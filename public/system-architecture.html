Provider Selection

The email provider is configured per-customer in the JSON config file. The Message Dispatcher Step Function routes to the appropriate provider Lambda based on the email_provider field. Each provider stores OAuth credentials in Secrets Manager using the naming convention bb-gtm-{customer}-{env}-comm-{provider}-credentials.

Isolation Mechanisms

  • Resource naming -- all AWS resources include customer and environment in the name: bb-gtm-{customer}-{env}-{module}-{resource}
  • No CDK cross-stack exports -- stacks reference each other by constructing ARNs from naming conventions, avoiding CloudFormation coupling
  • Runtime resolution -- Employee IDs, sender configs, and other customer-specific data are resolved at Lambda runtime, not baked into the deployment
  • Config-driven -- each customer has a dedicated JSON config file that drives all stack parameters

Schema Caching

Each MCP Lambda maintains its own in-memory schema cache with a 1-hour TTL. After adding new Airtable fields, you must force cold starts on the relevant Lambdas by updating their description (never use --environment Variables={...} as this replaces all env vars). Alternatively, invoke the schema Lambda with "refresh": true to refresh its cache specifically.
